# חיבור סוכן המשימות ל-Gemini

## מצב Spark — סביבת הניסוי

ברירת המחדל של האפליקציה היא Firebase AI Logic עם Gemini Developer API. המסלול
אינו דורש Cloud Functions, Secret Manager או מפתח Gemini בקוד, ולכן מתאים
לפרויקט Firebase במסלול Spark. יש להפעיל Firebase AI Logic ו-App Check במסוף.

הדפדפן טוען רק מידע שהמשתמש כבר מורשה לקרוא לפי Firestore Rules. לפני הפנייה
למודל המידע מצטמצם לשמות צוותים, תפקידים, כיתות, מועדים חסומים, כללים שאושרו
ושמות של משימות דומות שהמשתמש עצמו יצר. שמות ומזהי אנשי צוות אינם נשלחים
ל-Gemini; התאמת האנשים נעשית מקומית מול הרשומות המורשות.

המשימות הקיימות משמשות כזיכרון מפוצל: אין מסמך "מוח" גדול ואין צורך בטריגר.
משימות אישיות ומשימות ארגוניות שהמשתמש יצר משפיעות רק על ההצעות שלו. ידע
מוסדי נכנס להצעות לכלל הצוות רק דרך כללים ותבניות שמנהל אישר ושמר במסמך
ההגדרות של המוסד. אם Gemini או App Check אינם זמינים, המנוע המקומי עדיין
מחזיר הצעה מוסדית והיצירה הידנית נשארת זמינה.

## מצב שרת עתידי — Blaze

מפתח Gemini אינו נשמר בקוד, בקובצי `VITE_*` או בדפדפן. כאשר עוברים ל-Blaze,
הפונקציה `draftTaskWithAgent` יכולה לקבל גישה רק ל-Secret הייעודי בזמן ריצה.

1. בטלו או מחקו ב-Google AI Studio כל מפתח שנחשף בצילום מסך, בצ'אט או בלוגים.
2. צרו מפתח חדש ומוגבל לפרויקט ול-Gemini API.
3. מהשורש הריצו `firebase functions:secrets:set GEMINI_API_KEY` והדביקו את המפתח החדש בהנחיה האינטראקטיבית.
4. פרסו עם `firebase deploy --only functions:draftTaskWithAgent`.

אפשר לשנות מודל באמצעות פרמטר Cloud Functions בשם `GEMINI_TASK_MODEL`.
ברירת המחדל היא `gemini-flash-latest`. הסוכן אינו שומר משימה בעצמו; הוא מחזיר
טיוטה מובנית, והמשתמש חייב לאשר אותה במסך המשימות.
