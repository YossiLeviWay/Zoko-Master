# עדכון: Codex מקומי בלבד

בהתאם לבקשה המעודכנת, Codex זמין רק דרך השירות המקומי ב־127.0.0.1. הכפתור אינו מוצג באתר הציבורי, ושרת ההפעלה אינו מפעיל עוד את תור Firebase גם אם דגל החיבור הציבורי הישן הוגדר. ההפעלה: `npm run dev:codex`, כניסה לחשבון המנהל במחשב, ופתיחת Codex בזוקי. החשבון הראשון שמתחבר לשירות הוא בעל החיבור עד לעצירתו; אין נקודת גישה מהאינטרנט. כללי Firebase לא שונו.

הסעיפים להלן המתארים חיבור ציבורי נשמרים כתיעוד היסטורי של אפשרות שבוטלה.

# זוקי עם Codex — אתר ציבורי ושירות מקומי

## מצב הפרסום — 13 בספטמבר 2026

כפתור הבחירה ומנגנון החיבור מוכנים לפרסום. החיבור הציבורי כבוי כברירת מחדל: הדפדפן אינו קורא או כותב בתור Firebase עד להפעלת דגל הבנייה, והשירות אינו מפרסם זמינות עד להפעלה מפורשת. אין להפעיל `ZOKO_CODEX_PUBLIC_RELAY` או `VITE_ZOKO_CODEX_PUBLIC_RELAY` עם כללי הייצור הנוכחיים.

הבדיקה של כללי הייצור מצאה כלל המאפשר לכל משתמש מחובר לקרוא ולכתוב בכל המסד. לכן הוא אינו מגן על התור הפרטי. החלפתו בכללי הפרויקט מחייבת גם תיקון שאילתות קיימות: בדיקת הקצה הנוספת נכשלת בקריאת אנשי צוות באמצעות `schoolIds`, ויש קריאות קטלוג נוספות שאינן זמינות תחת הכללים המפורטים. בדיקות הבסיס באמולטור עברו, אך הן אינן מוכיחות שכל שאילתות האפליקציה תואמות לכללים.

בדיקת הקצה האבחונית מופעלת רק עם `ZOKO_TEST_PUBLIC_RELAY=1`, ותישאר חסומה לפני ההפעלה הציבורית. היא הורצה ונכשלה בקריאת ההקשר; אינה נספרת בין הבדיקות שעברו.

בקרת האישור דחתה הן שינוי בפונקציית הרשאה כללית והן יצירת כללי מעבר שמשמרים את הגישה הרחבה. שני הניסיונות לא בוצעו. נדרשת הסכמה להרחבת העבודה לתיקון ההרשאות והשאילתות לפני הפעלה ציבורית. הוראות השימוש בהמשך מתארות את ההתנהגות לאחר השלמת תנאי זה.


כפתור **Codex שלי** מופיע בזוקי באתר הציבורי למנהלי מוסד. הבקשות עוברות בתור פרטי ב־Firebase אל השירות המקומי, שמשתמש בחשבון ChatGPT שכבר מחובר ל־Codex במחשב. המחשב אינו נחשף לאינטרנט ואין חיבור ישיר מהאתר לכתובת localhost. אין שימוש ב־Cloud Functions, מפתח Firebase Admin, מפתח OpenAI API או שדרוג Blaze.

## הפעלה

דרושים Node 20.19 ומעלה, התקנת Codex עם חשבון מחובר, וקובץ הגדרות Firebase הקיים של האפליקציה. מתקינים את תלויות הפרויקט ואת תלויות העיבוד שכבר קיימות ב־functions:

```sh
npm ci
npm --prefix functions ci
npm run check:codex
npm run dev:codex
```

פותחים `http://127.0.0.1:5189/Zoko-Master/`, מתחברים לאפליקציה כמנהל המוסד, פותחים את זוקי ובוחרים **Codex שלי**. כפתור החיבור בודק את החשבון ואת הפרטיות באמצעות טקסט ותמונה סינתטיים, לפני העברת נתוני מוסד. אם Codex אינו מחובר, מתחברים אליו באפליקציית Codex וחוזרים לבדיקה. השאירו את השירות ואת פאנל Codex המקומי פתוחים. בחלון נוסף או במכשיר אחר פותחים את האתר הציבורי, מתחברים **לאותו חשבון זוקו ובאותו מוסד**, ובוחרים Codex שלי ואז התחברות. אפשר לחזור לזוקי הרגיל באתר בכל רגע; חשבון Codex עצמו אינו מנותק. סגירת פאנל החיבור המקומי מפסיקה את הגשר.

ב־macOS ההפעלה מזהה גם את העותק המותקן עם אפליקציית Codex. במקום אחר, אפשר לקבוע `ZOKO_CODEX_BIN` לנתיב ההפעלה. `ZOKO_CODEX_PORT` משנה את הפורט. השירות מאזין ב־127.0.0.1 בלבד ובודק Host ו־Origin מדויקים. כל פעולת API דורשת זהות Firebase של מנהל ומזהה חיבור זמני. המנהל הראשון שמתחבר הוא בעל הפיילוט עד להפעלה מחדש.

**נדרשים כללי Firebase המפורטים שבפרויקט.** כלל גורף המאפשר לכל משתמש מחובר גישה לכל המסד אינו מתאים לתור זה. פקודת ההפעלה המקומית אינה מפרסמת כללים ואינה משנה מסלול חיוב. הבדיקות באמולטור אינן מפרסמות דבר.

## זמינות וגישה מהאתר

- אין בחירת שם מודל טכני: הכפתור בוחר בין המנוע הרגיל של זוקי לבין Codex שלי.
- אסימון Firebase קצר חיים נשמר בזיכרון השירות בלבד. חלון החיבור המקומי מחדש אותו כל 30 שניות. אין אסימון, סיסמה או פרטי התחברות בתור Firebase או בקלט המודל.
- השירות בודק תור כל 10 שניות ומחדש סימון זמינות בערך כל 50 שניות. הזמינות פגה בתוך 90 שניות. זהות המנהל נבדקת שוב; שירות שני אינו יכול לקחת חיבור פעיל.
- התור, חלקי הבקשה והתגובה נמצאים תחת `users/{uid}/zokiPilot/{schoolId}`. כללי Firestore מגבילים אותם למנהל היוזם במוסד המתאים. מנהל אחר אינו מקבל גישה לחשבון Codex הזה.
- בקשה נרשמת לעיבוד רק בעסקה מקוונת, לאחר בדיקה חוזרת שהמחשב זמין. בקשה שפג תוקפה או שמשויכת לחיבור קודם אינה מתחילה ביצוע. מזהה ההצעה, חתימתה וגרסתה נבדקים באותו מנגנון מקומי.
- כשהמחשב אינו זמין בבחירת Codex, זוקי חוזר למנוע הרגיל עם הסבר. ניתוק בזמן עבודה אינו שולח את הבקשה למנוע אחר. טיוטה וקובץ לא נזרקים כדי לבצע מעבר אוטומטי; בביצוע שהתחיל יש לבדוק את הדוח ולחדש דרך Codex.
- קובץ מועבר בחלקים פרטיים קטנים ב־Firebase, עד מגבלת 20MB. חלקי הקלט נמחקים לאחר עיבוד, והדפדפן מוחק חלקים בסיום. שאריות פגות לאחר עשר דקות ומנוקות על ידי השירות במחזור ניקוי או בהפעלה הבאה; כאשר המחשב מנותק אין הבטחת מחיקה אוטומטית בזמן קבוע. ההצעות והשיחה נשמרות בנפרד כמקור האמת.
- אין שרת ענן בתשלום או Cloud Functions. קריאות התור והקבצים צורכות ממכסות Firestore החינמיות; חריגה או חסימת רשת יפסיקו את החיבור ולא ישדרגו את המסלול.

## מה אפשר לבצע

- קובץ אחד בכל בקשה: XLSX, CSV, PDF, PNG, JPEG או WebP; עד 20MB, מאה עמודי PDF ועשרת אלפים שורות טבלה. אין הרצת נוסחאות Excel: נקרא רק ערך מחושב ששמור בקובץ; חוסר בערך מוצג לבירור.
- גאנט: טווח תאריכים נפרס לאירועים יומיים מקושרים. שישי ושבת נכללים כברירת מחדל. קישור התוצאה פותח את חודש האירוע.
- מיפויים: יצירת תלמיד עם שיבוץ, תיק אישי והיסטוריה; יצירת מיפוי ציונים חסר; עדכון ציונים וחישובים; יצירת גיליון נוכחות חסר והזנת נוכחות; יצירת טבלה פדגוגית עם מדדים מטיפוסים מוגדרים.
- משימות חדשות: רשומה משותפת אחת, התקדמות אישית לכל משובץ, תצוגה בלוח הקיים והתראות בעלות מזהים יציבים. עדכון פרטים של משימות ישנות שומר על מנגנון ההתקדמות הקיים שלהן.
- התאמות חלופיות שמוצעות ואושרו נשמרות בחלק הפרטי של המנהל לפי מוסד ושנת לימודים. המודל מקבל את שמות הכיתות, השכבות והמחנכים בפועל, כולל אפשרויות מתחרות; הוא נדרש לבקש הבהרה כאשר הזיהוי אינו חד־משמעי.

המודל מציע פעולות בלבד. הקבצים, התאים והטקסט המצוטט מוגדרים כנתונים בלתי מהימנים, שאינם רשאים לשנות את ההוראות. כל שורה טבלאית צריכה להיות מקושרת לפעולה או להופיע ברשימת ההשמטות עם סיבה. ב־PDF ובתמונה הכיסוי נבדק לפי עמוד; זיהוי חזותי דורש בדיקה מפורשת של ההצעה. הבירורים וההצעה נשארים בזוקי.

ההצעה מציגה מקור, מטרות מזוהות מתוך Firebase, ערך קודם ומוצע, סיבה והתראות. אפשר לערוך שדות, להשמיט פריטים, לאשר התאמה לא ודאית או לבקש תיקון בשיחה. עריכה יוצרת גרסה חדשה לפני האישור. בקשה לתקן ביצוע קודם יוצרת הצעה חדשה על סמך הנתונים העדכניים.

## שמירה, חידוש ופרטיות

- REST של Firestore מקבל אסימון Firebase של המשתמש המחובר; כללי Firebase הם סמכות האישור. לפני כל מנת ביצוע נבדק שוב שהמשתמש מנהל במוסד הנכון. האסימון אינו מועבר למודל.
- נשמרים מסמכי הצעה מחולקים לעמודים, היסטוריית שיחה ותוצאות פרטיות ב־`users/{uid}/zokiPilot/{schoolId}`. מסך דוח הייבוא נגיש מהתוצאה, רק למנהל היוזם. המיפויים עצמם מקבלים הרשאות לפי הכיתה.
- אין שמירת שיחות, קבצים, טיוטות או תלמידים ב־localStorage, ב־sessionStorage או ב־IndexedDB. מעבר מוסד או יציאה מנקים את מצב השיחה. לאחר רענון נקרא רק העותק המורשה ב־Firebase. בשיחה חדשה ניתן להמשיך מהטקסט האחרון של זוקי הרגיל, שנקרא מאותו חשבון ומוסד ב־Firebase.
- כל פנייה ל־Codex משתמשת בשיחה `ephemeral`. היסטוריה, טלמטריה, יצוא OTEL, פקודות notify, hooks, shell, יישומים ושרתי MCP חיצוניים מושבתים בתהליך הייעודי. אין למודל כלי המאפשר לאשר או לבצע את ההצעה בעצמו.
- הקבצים מפוענחים בזיכרון בלבד. תיקיית העבודה הזמנית ריקה ומוגנת; נמחקת בעצירה, ושאריות של תהליך שכבר הסתיים מנוקות בהפעלה הבאה. ניתוק מפסיק את תהליך הסוכן; חיבור שלא פעיל חמש דקות מנוקה מהזיכרון.
- קובץ מקומי יחיד, `.zoki-local/integrity.key`, מכיל מפתח אקראי לאימות חתימת ההצעות. הוא **אינו מכיל שיחה, מידע מוסדי או פרטי התחברות**. הרשאותיו 0600, תיקייתו 0700, הוא מוחרג מ־Git ונחסם להגשה דרך HTTP ו־Vite. אין למחוק אותו באמצע ייבוא שרוצים לחדש: החלפתו מבטלת אימות של הצעות ישנות.
- כתיבה משתמשת בתנאי גרסה ובמסכות שדות; חותמות זמן ושדות שלא נערכו נשמרים. כל מנת כתיבה נשמרת עם נקודת חידוש באותה עסקה. לאחר אובדן תגובת שרת נבדקת נקודת החידוש; כאשר הרשת עדיין מנותקת מוצג שהאישור טרם התקבל, בלי להבטיח ביטול שלא אומת.
- דוח הייבוא מבחין בין הושלם, נשמר חלקית, הושמט ולא בוצע. חידוש אינו משכפל פעולות שכבר נשמרו. שינוי מקביל בנתונים עוצר את הפעולה במקום לדרוס אותו. ארכוב אינו מחיקה קבועה.

## גבולות הפיילוט

- חשבון Codex קיים אחד על מחשב אחד. האתר הציבורי נגיש גם ממכשיר אחר, אך רק לאותו מנהל שחיבר את המחשב. חיבור חשבונות Codex של מנהלים נוספים אינו חלק מהפיילוט. אין עבודה כשהשירות והחיבור המקומי אינם פעילים. החיבור משתמש במכסות החשבון הקיים.
- פעולות של גרסה ישנה מאוד של משימות משותפות באחסון legacy עם `assignmentVersion: 2` נחסמות במפורש; נדרש מסלול התאמה לפני עריכתן. לא מופעל עבורן שרת בתשלום ולא משתנה בשקט מנגנון ההשלמה.
- העברת תלמיד קיים בין כיתות עדיין מופנית למסלול ההעברה הקיים; יצירת תלמיד חסר עם שיבוץ נתמכת. שכפול של מספר זהות קיים אינו יוצר תלמיד נוסף.
- שינויים מבניים בעמודות, שיוכים מורכבים או תיקונים מרובים נעשים באמצעות בקשה נוספת בשיחה. העורך הישיר מציע שדות פשוטים. מיפוי פדגוגי פתוח לקריאה מהכיתה ומקישור התוצאה; כתיבתו נעשית בהצעה מאושרת.
- מטען ניתוח העולה על 600KB או חילוץ מעל 8MB נחסמים במפורש. הגבולות מונעים חיתוך אוטומטי בגלל מגבלת הקשר. יש לצמצם או לפצל את הקובץ במקרה כזה.
- בדיקת הסמן הסינתטי היא בדיקת רגרסיה להתקנה המקומית בזמן החיבור, ואינה טענה על מדיניות השמירה בענן של ספק המודל. לא נבדקו ולא יובאו במסגרת הפיתוח נתוני תלמידים אמיתיים.

## בדיקות

```sh

```

בדיקות האמולטור פועלות בפרויקט `demo-zoko-security`. מתאם ה־REST מאפשר כתובת אמולטור רק לפרויקט עם קידומת `demo-` ורק ב־localhost. בדיקות החיבור החי משתמשות אך ורק בסמנים ובתמונה סינתטיים; אינן מפעילות ייבוא ואינן משנות נתוני מוסד.
