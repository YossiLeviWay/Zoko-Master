# זוקי עם Codex — עבודה באתר הרגיל דרך המחשב האישי

## הפעלה

1. לחץ פעמיים על `חיבור זוקו.command` בתיקיית הפרויקט. תוכנת החיבור פועלת ברקע ופותחת חלון מקומי.
2. התחבר לזוקו באותו חשבון מנהל ובאותו מוסד שבהם אתה משתמש באתר.
3. בזוקי בחר **Codex שלי → חיבור המחשב לאתר**. ההתחברות ובדיקת הפרטיות משתמשות בנתונים סינתטיים לפני העברת מידע מוסדי.
4. פתח את האתר הרגיל, ובזוקי בחר **Codex שלי → התחברות ל־Codex שלי**.
5. אפשר לסגור את החלון המקומי. תוכנת החיבור צריכה להמשיך לפעול. אחרי כיבוי המחשב או עצירת התהליך יש להפעיל ולחבר מחדש.

אפשר גם להפעיל ידנית באמצעות `npm run dev:codex`. אין צורך להשאיר את חלון Codex Desktop פתוח; נדרשים התקנה, התחברות Codex תקינה ואינטרנט. Node ותלויות הפרויקט צריכים להיות מותקנים.

## החיבור וההרשאות

האתר ותוכנת החיבור מתקשרים דרך תיבת בקשות פרטית ב־Firebase. רק המחשב יוזם חיבורים לאינטרנט; השרת המקומי מאזין ב־127.0.0.1 בלבד. אין פתיחת פורט לאינטרנט, מפתח Firebase Admin, מפתח OpenAI API, Cloud Function או שינוי למסלול Blaze.

החשבון הראשון שמחובר מקומית הוא בעל החיבור עד לעצירת השירות. התיבה נמצאת תחת `users/{uid}/zokiPilot/{schoolId}`. מנהל אחר, גם באותו מוסד, אינו רשאי לקרוא או לכתוב בה. תפקיד המנהל וחברותו במוסד נבדקים מחדש במהלך העבודה. ניתוק המחשב אפשרי מהחלון המקומי; מעבר מוסד או יציאה מהחשבון המקומי מנתקים את החיבור. יציאה מהאתר הציבורי מנקה את השיחה בזיכרון ומבטלת בקשה ממתינה, ללא שיתוף החשבון עם משתמש אחר.

אסימון Firebase ואסימון החידוש נשמרים בזיכרון התהליך בלבד. החידוש מתבצע ישירות מול Firebase ואינו תלוי בחלון דפדפן פתוח. הם אינם נשמרים בקובץ, בתיבת הבקשות, בקלט Codex או בלוגים. פרטי ההתחברות של Codex נשארים בניהול Codex.

`privacy-gate.rules` הוא תיקון ממוקד לכללים הפעילים בייצור: הוא סוגר את אזור Codex לבעליו ושומר על התנהגות הנתיבים האחרים. הוא אינו מחליף את הגירת ההרשאות הכוללת שב־`firestore.rules`. סקריפט הפרסום נעצר אם הכללים הפעילים השתנו מהבסיס שנבדק. אין להפעילו שוב כדרך כללית לפריסת הרשאות.

הדפדפן מאשר בקשה בתור רק בעסקה מקוונת לאחר בדיקת זמינות המחשב. כל בקשה קשורה למזהה החיבור, בעל החשבון והמוסד. שינוי בנתונים דורש אישור ההצעה המדויקת; אין העברה אוטומטית של ביצוע למנוע אחר לאחר תקלה. זוקי הרגיל נשאר זמין כשאין חיבור. קבצים זמניים בתיבה מנוקים אחרי שימוש או בהפעלה הבאה; `expiresAt` אינו מנגנון מחיקה מובנה של Firebase.

השרת אינו כותב יומני תוכן. `.zoki-local/connector.pid` שומר רק את מזהה התהליך. מפתח חתימת ההצעות נשמר בנפרד כמתואר בהמשך.

## מה אפשר לבצע

- קובץ אחד בכל בקשה: XLSX, CSV, PDF, PNG, JPEG או WebP; עד 20MB, מאה עמודי PDF ועשרת אלפים שורות טבלה. אין הרצת נוסחאות Excel: נקרא רק ערך מחושב ששמור בקובץ; חוסר בערך מוצג לבירור.
- גאנט: טווח תאריכים נפרס לאירועים יומיים מקושרים. שישי ושבת נכללים כברירת מחדל. קישור התוצאה פותח את חודש האירוע.
- מיפויים: יצירת תלמיד עם שיבוץ, תיק אישי והיסטוריה; יצירת מיפוי ציונים חסר; עדכון ציונים וחישובים; יצירת גיליון נוכחות חסר והזנת נוכחות; יצירת טבלה פדגוגית עם מדדים מטיפוסים מוגדרים.
- משימות חדשות: רשומה משותפת אחת, התקדמות אישית לכל משובץ, תצוגה בלוח הקיים והתראות בעלות מזהים יציבים. עדכון פרטים של משימות ישנות שומר על מנגנון ההתקדמות הקיים שלהן.
- התאמות חלופיות שמוצעות ואושרו נשמרות בחלק הפרטי של המנהל לפי מוסד ושנת לימודים. המודל מקבל את שמות הכיתות, השכבות והמחנכים בפועל, כולל אפשרויות מתחרות; הוא נדרש לבקש הבהרה כאשר הזיהוי אינו חד־משמעי.

המודל מציע פעולות בלבד. הקבצים, התאים והטקסט המצוטט מוגדרים כנתונים בלתי מהימנים, שאינם רשאים לשנות את ההוראות. כל שורה טבלאית צריכה להיות מקושרת לפעולה או להופיע ברשימת ההשמטות עם סיבה. ב־PDF ובתמונה הכיסוי נבדק לפי עמוד; זיהוי חזותי דורש בדיקה מפורשת של ההצעה. הבירורים וההצעה נשארים בזוקי.

ההצעה מציגה מקור, מטרות מזוהות מתוך Firebase, ערך קודם ומוצע, סיבה והתראות. אפשר לערוך שדות, להשמיט פריטים, לאשר התאמה לא ודאית או לבקש תיקון בשיחה. עריכה יוצרת גרסה חדשה לפני האישור. בקשה לתקן ביצוע קודם יוצרת הצעה חדשה על סמך הנתונים העדכניים.

## שמירה, חידוש ופרטיות

- REST של Firestore מקבל אסימון Firebase של המשתמש המחובר; כללי Firebase הם סמכות האישור. לפני כל מנת ביצוע נבדק שוב שהמשתמש מנהל במוסד הנכון. האסימון אינו מועבר למודל.
- נשמרים מסמכי הצעה מחולקים לעמודים, היסטוריית שיחה ותוצאות פרטיות ב־`users/{uid}/zokiPilot/{schoolId}`. מסך דוח הייבוא נגיש מהתוצאה, רק למנהל היוזם. המיפויים עצמם מקבלים הרשאות לפי הכיתה.
- אין שמירת שיחות, קבצים, טיוטות או תלמידים ב־localStorage, ב־sessionStorage או ב־IndexedDB. מעבר מוסד או יציאה מנקים את מצב השיחה. לאחר רענון נקרא רק העותק המורשה ב־Firebase. בשיחה חדשה ניתן להמשיך מהטקסט האחרון של זוקי הרגיל, שנקרא מאותו חשבון ומוסד ב־Firebase.
- כל פנייה ל־Codex משתמשת בשיחה `ephemeral`. היסטוריה, טלמטריה, יצוא OTEL, פקודות notify, hooks, shell, יישומים ושרתי MCP חיצוניים מושבתים בתהליך הייעודי. אין למודל כלי המאפשר לאשר או לבצע את ההצעה בעצמו.
- הקבצים מפוענחים בזיכרון בלבד. תיקיית העבודה הזמנית ריקה ומוגנת; נמחקת בעצירה, ושאריות של תהליך שכבר הסתיים מנוקות בהפעלה הבאה. ניתוק מפסיק את תהליך הסוכן; חיבור שלא פעיל חמש דקות מנוקה מהזיכרון.
- קובץ מקומי `.zoki-local/integrity.key`, מכיל מפתח אקראי לאימות חתימת ההצעות. הוא **אינו מכיל שיחה, מידע מוסדי או פרטי התחברות**. הרשאותיו 0600, תיקייתו 0700, הוא מוחרג מ־Git ונחסם להגשה דרך HTTP ו־Vite. אין למחוק אותו באמצע ייבוא שרוצים לחדש: החלפתו מבטלת אימות של הצעות ישנות.
- כתיבה משתמשת בתנאי גרסה ובמסכות שדות; חותמות זמן ושדות שלא נערכו נשמרים. כל מנת כתיבה נשמרת עם נקודת חידוש באותה עסקה. לאחר אובדן תגובת שרת נבדקת נקודת החידוש; כאשר הרשת עדיין מנותקת מוצג שהאישור טרם התקבל, בלי להבטיח ביטול שלא אומת.
- דוח הייבוא מבחין בין הושלם, נשמר חלקית, הושמט ולא בוצע. חידוש אינו משכפל פעולות שכבר נשמרו. שינוי מקביל בנתונים עוצר את הפעולה במקום לדרוס אותו. ארכוב אינו מחיקה קבועה.

## גבולות הפיילוט

- חשבון Codex קיים אחד על מחשב אחד. האתר הציבורי נגיש גם ממכשיר אחר, אך רק לאותו מנהל שחיבר את המחשב. חיבור חשבונות Codex של מנהלים נוספים אינו חלק מהפיילוט. אין עבודה כשהשירות והחיבור המקומי אינם פעילים. החיבור משתמש במכסות החשבון הקיים.
- פעולות של גרסה ישנה מאוד של משימות משותפות באחסון legacy עם `assignmentVersion: 2` נחסמות במפורש; נדרש מסלול התאמה לפני עריכתן. לא מופעל עבורן שרת בתשלום ולא משתנה בשקט מנגנון ההשלמה.
- העברת תלמיד קיים בין כיתות עדיין מופנית למסלול ההעברה הקיים; יצירת תלמיד חסר עם שיבוץ נתמכת. שכפול של מספר זהות קיים אינו יוצר תלמיד נוסף.
- שינויים מבניים בעמודות, שיוכים מורכבים או תיקונים מרובים נעשים באמצעות בקשה נוספת בשיחה. העורך הישיר מציע שדות פשוטים. מיפוי פדגוגי פתוח לקריאה מהכיתה ומקישור התוצאה; כתיבתו נעשית בהצעה מאושרת.
- מטען ניתוח העולה על 600KB או חילוץ מעל 8MB נחסמים במפורש. הגבולות מונעים חיתוך אוטומטי בגלל מגבלת הקשר. יש לצמצם או לפצל את הקובץ במקרה כזה.
- בדיקת הסמן הסינתטי היא בדיקת רגרסיה להתקנה המקומית בזמן החיבור, ואינה טענה על מדיניות השמירה בענן של ספק המודל. לא נבדקו ולא יובאו במסגרת הפיתוח נתוני תלמידים אמיתיים.

## בדיקות

```sh
npm run test:codex
npm run test:unit
npm run test:emulator
npm run lint
npm run typecheck
npm run build
```

בדיקות האמולטור פועלות בפרויקט `demo-zoko-security`. מתאם ה־REST מאפשר כתובת אמולטור רק לפרויקט עם קידומת `demo-` ורק ב־localhost. בדיקות החיבור החי משתמשות אך ורק בסמנים ובתמונה סינתטיים; אינן מפעילות ייבוא ואינן משנות נתוני מוסד.

ב־13 בספטמבר 2026 עברו 191 בדיקות יחידה, 203 בדיקות הרשאות ואינטגרציה באמולטורים, 31 בדיקות שרת ובדיקת PDF, וכן lint, בדיקת הטיפוסים הקיימת ובנייה. בדיקת קצה מול Codex המחובר בפועל קיבלה CSV סינתטי, הכינה שלושה אירועים יומיים ולא כתבה אירועים לפני אישור. הפאנל נבדק בדפדפן עם מידע סינתטי, לרבות עריכה לפני אישור ורוחב נייד; בדיקת HTTP אישרה שקובץ החתימה אינו נגיש.

כללי Firebase קרובים למגבלת גודל המקור. חלק מההבדלים בקובץ הם קיצור הפניות חוזרות לאותו מסמך ושינוי סדר בדיקות קיימות כדי להישאר במגבלות הגודל, הביטויים והקריאות. הרשאות הפיילוט נוספו במסלולים מוגדרים בלבד. פרסום כללים לפרויקט החי הוא שלב נפרד מבדיקות האמולטור, במסגרת בקשת ההפעלה הציבורית.

החיבור מתבסס על [Codex App Server](https://learn.chatgpt.com/docs/app-server) ועל [הגדרות Codex](https://learn.chatgpt.com/docs/config-file/config-reference). הפיילוט אינו משנה את התקנת Codex או את קובץ ההגדרות הראשי שלה.
